# AR2EEnemyCreator AGENTS

## ユーザーとのやり取り

- すべての回答・質問は日本語で行う。ユーザーも日本語入力を想定する。

## 承認依頼時の説明

- コマンド実行やファイル修正で承認が必要な場合は、事前にコマンドの動作内容・変更対象・修正意図を簡潔に説明してから承認を求める。

## ディレクトリ構成と変更範囲

- `index.html` / `script.js` / `style.css` / `README.md` に加えて、このツール固有の `SPEC/`・`TODO.md` を管理する。変更は必ず AR2EEnemyCreator 配下に閉じる。
- 共有アセットは存在しない想定のため、他ツールのコードは参照せず必要な処理は本ディレクトリ内に実装・複製する。
- `SPEC/` 配下の仕様を更新した際は、該当する TODO を `TODO.md` で同時に移動・削除し、目次や参照リンクの整合も取る。
- `TODO.md` のタスクを実装するときは `SPEC/` に記載済みの仕様やフォーマットを崩さず反映し、動作に問題がなければ仕様を適切な `SPEC/*.md` ファイルに追記したうえで `TODO.md` から該当項目を削除する。

## 開発・テスト手順

- 動作確認は `index.html` をブラウザへドラッグ＆ドロップ（もしくは直接開く）だけで行い、ローカルサーバーや `xdg-open` は使用しない。
- README記載の「Download ZIP」手順を先頭から最後まで手動で踏む。フォーム入力、localStorage 永続化、XML/ZIP出力、チャットパレット生成、スキルライブラリ操作など主要フローを都度確認する。
- 新挙動を検証する前には `chrome://settings/siteData` でブラウザストレージを消去し、クリーン状態で再テストする。

## コーディングスタイル

- JavaScriptはモダンESを使用し、`const`/`let`、アロー関数、2スペースインデントを厳守する。
- 変数名は役割が伝わる日本語またはcamelCaseとし、DOM参照には `nameEl` / `submitBtn` のように `El`/`Btn` 接尾辞を付ける。
- CSSクラスはケバブケースでまとめ、コンポーネント単位で宣言を整理する。
- 画面要素を追加・変更する場合は既存UIコンポーネントの配色・余白・文字サイズを踏襲し、他セクションと一体感のあるレイアウトを維持する（必要に応じて共通クラスを用意する）。

## ドキュメントと成果物

- READMEは利用者視点の情報（ダウンロード方法・起動方法・機能説明・注意事項）のみに限定し、開発フローや内部向け情報は含めない。
- `.gitignore` で管理されていないファイル（未共有データなど）はREADMEへ記載しない。
- 配布用ZIPは `cd AR2EEnemyCreator && zip -r ../dist/AR2EEnemyCreator.zip index.html script.js style.css README.md` を基本とし、作成前に同名の旧zipを削除して最新ファイルのみが入るようにする。
