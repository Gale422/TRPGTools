#### スキル・パワーライブラリの活用

このアプリケーションには「スキル・パワーライブラリ」機能があり、汎用的なスキルを事前に登録しておき、エネミー作成時に選択して追加できる。

**注意点**:

- 既存のエネミーデータには`//--- ==========汎用エネミースキル==========`のような参照用スキルリストが含まれている場合があるが、これはXMLをコピーして作成した際に削除し忘れた残骸
- 本来はスキル・パワーライブラリから必要なスキルを選択して追加し、不要な参照用リストは削除すべき
- チャットパレットには実際にエネミーが使用するスキルのみを含めることを推奨

**スキルのカテゴリ分け**:

既存のエネミーデータで見られる`_/_/_/_/_/武器_/_/_/_/_/`のようなカテゴリ区切りは、以下のような分類を意図している：

- **武器**: 武器攻撃系スキル
- **魔法**: 魔法攻撃・魔術系スキル
- **特殊**: 特殊攻撃系スキル
- **拡張**: スキル拡張・変更系
- **強化**: 自身強化系
- **支援・妨害**: 味方支援・敵妨害系
- **種族**: 種族専用スキル
- **フェイス**: フェイス専用スキル
- **パワー**: パワースキル

将来的には、スキル・パワーライブラリにカテゴリやタグ機能を実装し、これらの分類で検索・フィルタリングできるようにする予定（[TODO.md](TODO.md)を参照）。

#### ダメージコマンドへの注釈

実運用では、ダメージコマンドに注釈をつけるケースがある：

```txt
2D6+410 ダメージ《大剣》※鬼の爪の効果込
2D6+350 ダメージ《大剣》
```

このように、特定のスキル効果が含まれているかどうかを明記することで、状況に応じたコマンドを選びやすくする。

#### バフコマンドのバリエーション

セッション中に頻繁に使用するバフ付与コマンドを、効果強度別に複数用意しておくことがある：

```txt
t&衰弱/1/9999 対象に衰弱を与える
t&衰弱/2/9999 対象に衰弱を与える
t&衰弱/3/9999 対象に衰弱を与える
```

また、自身にバフを付与するコマンドも用意：

```txt
&毒/0/9999 バフ追加
&衰弱/0/9999 バフ追加
```

#### 能力値の設定

**推奨される設定方法**:

1. **能力基本値を設定**: すべてのエネミーで能力基本値を適切に設定することを推奨
2. **能力値の入力モード**: 「能力基本値で入力」または「能力値で入力」のいずれかを選択
3. **行動値・移動力**: 能力値から自動計算される値を基本とし、必要に応じて補正値を追加、または直接入力モードで設定

**注意点**:

- 既存のエネミーデータで能力値が全て0になっているケースがあるが、これは作成時間の都合やプレイヤーが参照しないことを前提とした手抜き
- 本来はすべてのエネミーに適切な能力値を設定すべき
- モブエネミー以外で能力値が未設定の場合、プレイヤーが能力値判定を要求するスキルを使用した際に対応できない

#### 大規模エネミーの例

レベル100のボスエネミー「禁時機構・ネメシスフォールト」の実例：

- HP: 15,000
- 行動値: 35（非常に高い）
- 物防: 50、魔防: 100
- ドロップ品: 4段階（2-6、7-17、18-23、24-）
- ドロップ品の個数指定: `時空の歯車(6,000G)x20`

### コードの構造化

> **関連**: 実装済み仕様の各機能は、以下のクラス構造で実装されている

- **オブジェクト指向**: クラスを利用して構造化
- **主要クラス**:
  - `DataManager`: ローカルストレージ管理
  - `Enemy`: エネミーデータモデル
  - `Skill`: スキルデータモデル
  - `EnemyManager`: エネミー管理
  - `SkillLibraryManager`: スキルライブラリ管理
  - `XMLGenerator`: XML生成
  - `UIManager`: UI管理
  - `App`: アプリケーションエントリーポイント

### ファイル分割

- 現在は単一の`script.js`で管理
- ファイルを分割する場合は、以下の点に注意:
  - 別ファイルから呼び出されていない関数や変数は、そのファイル内でしか参照できないようにスコープを区切る
  - どのファイルから呼び出されているのかを把握できるようにする
- 1ファイルの方がわかりやすい場合は、無理に分割しない

### 計算処理の原則

- **端数処理**: 割り算などの計算の結果として端数が発生した場合は、基本的に**切り捨て**
- 例: 能力基本値を3で割った値が能力値となる → `Math.floor(baseValue / 3)`

### エネミー識別の仕組み

> **関連仕様**:
>
> - [基本情報の管理](03-basic-info.md#基本情報の管理)の名称、分類、レベル、属性が公開される
> - [リソースの自動計算](05-resources.md#リソースの自動計算)の物理防御力と魔法防御力の比較結果が公開される
> - [スキル・パワーの管理](07-skills-powers.md#スキルパワーの管理)のスキル一覧が公開される
> - [チャットパレットの構造](08-xml-generation.md#チャットパレットの構造)の「識別公開情報」セクションに出力される

エネミー識別判定が成功した場合、以下の内容が公開される:

- エネミーの名称
- 分類
- レベル
- 属性
- 物理防御力と魔法防御力のどちらが高いか
- 取得しているエネミースキル

チャットパレットの「識別公開情報」セクションで、これらの情報を一度に表示できるようにする。

### チャットパレットのパラメータ参照

> **関連仕様**:
>
> - [チャットパレットの構造](08-xml-generation.md#チャットパレットの構造)で使用されるパラメータ参照の仕組み
> - [ドロップ品の管理](06-drop-items.md#ドロップ品の管理)のドロップ品は`{範囲}`形式で参照される
> - [スキル・パワーのnote要素](08-xml-generation.md#スキルパワーのnote要素)のスキルは`{スキル名}`形式で参照される
> - [基本情報の管理](03-basic-info.md#基本情報の管理)の情報は`{name}`、`{分類}`、`{レベル}`、`{属性}`形式で参照される

チャットパレット内で`{パラメータ名}`を使用すると、そのパラメータの値で置き換えられる。

例:

```txt
{5-8}  → 妖精の上等な服(300G)
{name} → ドライアド
{分類} → 妖精
```

### 保守性の考慮

- **可読性**: 人間が読みやすいコードを心がける
- **保守性**: 将来の修正や拡張を考慮した設計
- **一貫性**: コーディングスタイルを統一
- **ドキュメント**: JSDocコメントで関数やクラスを説明
